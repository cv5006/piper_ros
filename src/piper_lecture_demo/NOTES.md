## 설계 결정

### 숫자를 어디에 띄우나 — rviz2 에 오버레이가 없다

rviz2 기본 플러그인에 **화면 고정 HUD 가 없다.** 3D 씬 안에 그리는 것들뿐이고, 오버레이는
서드파티(`rviz-2d-overlay-plugins` 등) 설치가 필요하다.

**숫자판을 이미지로 그려 보낸다.** `/manipulability_readout` 의 `sensor_msgs/Image` 를
rviz 기본 **Image 디스플레이**가 받는다.

- 카메라를 움직여도 크기·위치가 안 변하고 팔에 안 가린다.
- 추가 설치 없음. numpy + opencv 만 쓰고 `cv_bridge` 없이 Image 를 직접 채운다.
- 반축 셋이 **막대**로 나온다 (1.0 기준이라 자세끼리 비교된다).
- 6자유도 `σ_min < 1e-3` 이면 **SINGULAR** 가 빨갛게 뜬다. `wrist` 에서 타원체는 둥근데
  이 글씨만 켜지는 것이 핵심 장면이다.

| `readout:=` | `image`(기본) | `marker` | `both` | `none` |
|---|---|---|---|---|
| | 2D 숫자판 | 3D 텍스트 | 둘 다 | 타원체만 |

### IK 해를 왜 Marker 로 그리나 — MoveIt 디스플레이는 SRDF 를 요구한다

MoveIt **Trajectory 디스플레이**는 로봇 모델을 **URDF + SRDF 둘 다**로 만든다.
URDF 스택에는 `robot_description_semantic` 이 없어 죽는다.

```
[moveit_rdf_loader.rdf_loader]: Unable to parse SRDF
```

빨간 오류만 남고 **아무것도 안 그려진다.** 링크 메시를 Marker 로 직접 놓는 쪽으로 바꿨다.

| 얻은 것 | |
|---|---|
| 스택을 안 가린다 | URDF · MoveIt 어디서든 같게 보인다 |
| 안 깜박인다 | 애니메이션 자체가 없다 (아래) |
| 색·투명도를 쥔다 | `alpha` 파라미터 |

⚠ **DELETEALL 마커에 `ns` 를 넣지 말 것.** rviz 가 디스플레이를 **오류로 표시**하면서도
**그리기는 정상**으로 해서 원인을 못 찾는다. 트리 아이콘만 빨갛다.

### 증상 — 「타원체가 로봇을 안 따라간다」

원인은 **`/joint_states` 발행자가 둘 이상.** 서로 덮어써서 `robot_state_publisher` 는
한쪽 값으로 TF 를, manipulability 는 다른 쪽 값으로 타원체를 그린다. 둘 다 에러를 안 낸다.

- 흔한 원인은 **앞서 띄운 데모가 살아 있는 것.** manipulability 가 감시해 경고한다.
- 버그가 아니라 이 레포의 성질이다. `/joint_states` 가 **명령 토픽**이라 마지막에 쓴 쪽이
  이긴다 — 강의 M6-1 이 다루는 사실이다.

```bash
ros2 topic info /joint_states --verbose
pkill -f joint_state_publisher
```

### 증상 — 「로봇이 계속 깜박거린다」

원인은 MoveIt **Trajectory 디스플레이의 애니메이션 재생.** `Loop Animation` 이 켜져 있으면
유령 로봇이 나타났다 사라진다. 화면 연속 캡처로 프레임 간 변화 측정 (0.15초 간격):

| | 바뀌는 화소 |
|---|---|
| `Loop Animation: true` | **6.05 %** — 두 상태를 오간다 |
| `Loop Animation: false` | **0.00 %** |

**지금은 없다.** Marker 로 바꾸며 애니메이션이 사라졌다. 같은 방법으로 재면 **0.00 %**.
남은 Trajectory 디스플레이는 `MotionPlanning`(계획된 경로) 하나이고, 그쪽은 재생되는 게 맞다.

## workspace 의 두 구름 — 이름에 주의

| 토픽 | 뜻 |
|---|---|
| `/workspace/reachable` | **닿기만 하면 되는 영역.** 자세 무관 |
| `/workspace/oriented` | **정해둔 접근 방향으로 닿는 영역** |

```python
# TCP 프레임의 z 축이 월드 -Z(바닥) 과 이루는 각이 허용치 안인가
T[:3, 2] @ [0, 0, -1] >= cos(approach_tol_deg)
```

- `link6` 의 `+z` 가 손가락 쪽 (URDF 확인 — `link6 → link7` 방향과 내적 **1.0000**).
- 축 둘레 회전(`joint6`)은 자유 — 대칭 2지 그리퍼에는 상관없다.
- ⚠ **교과서의 dexterous workspace 가 아니다.** 그쪽은 「**모든** 자세로 닿는 점」이고
  6축에서는 대개 텅 빈다. 여기 것은 「접근 방향 **하나**로 닿는가」라서 이름도 `oriented` 다.
- **허용각 없는 「작업영역의 몇 %」 는 무의미하다.**

| 허용각 | 5° | 15° | **25°** | 35° | 45° | 60° | 90° |
|---|---|---|---|---|---|---|---|
| 부피 기준 | 0.9 % | 2.7 % | **4.3 %** | 10.1 % | 15.5 % | 27.7 % | 54.6 % |

(기본 격자 `[11,13,13,5,5,1]`, 2 cm 복셀)

## 특이점 판정 기준

> **특이점은 부피가 0 이 되는 것이 아니라 차원이 하나 사라지는 것이다.
> 부피가 0 이 되는 것은 그 결과일 뿐이다.**

**판정은 `σ_min` 으로, `w` 는 여유의 총량 지표로.**

### 참·거짓으로는 셋이 같다

타원체는 관절속도 단위구 `‖q̇‖ ≤ 1` 의 상이다. 반축이 σ, `w = √det(JJᵀ) = σ₁σ₂σ₃` 가 부피다.

```
det J = 0   ⟺   σ_min = 0   ⟺   w = 0   ⟺   특이점
```

M3-4 를 M3-3 의 극한으로 배치한 구성이 옳다.

### 「얼마나 가까운가」에서는 갈린다

`w` 는 곱이라 두 원인이 섞인다.

| w 가 작다 | 원인 | 특이점인가 |
|---|---|---|
| 한 축이 죽어간다 | 차원이 무너지는 중 | **그렇다** |
| 세 축이 다 작다 | 그냥 느린 자세 | 아니다 |

반례가 프리셋에 들어 있다.

| preset | σ (선속도) | **w** | cond | σ_min (6×6) |
|---|---|---|---|---|
| `elbow` | 0.929 / 0.755 / **0.012** | **0.00841** | 77.4 | 0.000050 |
| `slow` | 0.443 / 0.283 / **0.068** | **0.00851** | 6.5 | 0.0238 |

**부피가 1 % 이내로 같은데 조건수는 12 배, `σ_min` 은 475 배 차이난다.**
두 프리셋을 연달아 재생하면 대비가 한 화면에서 끝난다.

- 무작위 40,000 자세에서 `log w` ↔ `log σ_min` 상관 **0.6483** (`log cond` 와는 −0.9465).
- **`σ_min` 이 더 작은데 `w` 는 3 배 큰** 자세 쌍이 실재한다.
- 특이점 근처에서 `w ≈ σ₁σ₂ · σ_min` 인데 `σ₁σ₂` 가 0.026 ~ 0.715 로 **28 배** 흔들린다.
  **고정 `w` 임계값은 고정 `σ_min` 임계값이 아니다.**
- ⚠ `w` 는 σ 의 **세제곱 차원**. 기준점을 플랜지 → TCP 로만 옮겨도 `w` 가
  0.0183 → 0.0569 로 **3.1 배** (σ 는 1.2 ~ 2 배).

### 지표 셋은 병존한다

| 지표 | 쓰는 자리 |
|---|---|
| `w = √det(JJᵀ)` | 타원체 부피. 설계 · 성능 |
| `κ = σ_max/σ_min` | 수치 조건, 등방성, **실시간 감속 임계값** |
| `σ_min` | 특이점까지의 거리 |

**`σ_min` 과 `κ` 는 경쟁 관계가 아니다.** Eckart–Young 에 의해

- `σ_min(J)` = 랭크 결손까지의 최소 섭동 → **절대 거리**
- `1/κ = σ_min/σ_max` → 같은 것을 J 크기로 나눈 **상대 거리**

선택은 "절대냐 상대냐"이지 "무엇이 표준이냐"가 아니다.

| | 재는 것 | 성질 |
|---|---|---|
| `σ_min` | 최악 방향 속도 이득. `‖q̇‖ ≥ ‖v‖ / σ_min` | **차원 있음.** 크기·단위에 따라 변한다 |
| `cond` | 비등방성. 최속/최저속 비 | **무차원 · 스케일 불변** |

⚠ 원 출처(Yoshikawa · Salisbury/Craig · Klein/Blake · Merlet 등)는 **이 저장소에서
검증하지 않았다.** Eckart–Young 관계와 이 문서의 측정값은 확인된 것이다.

### ⚠ 6×6 Jacobian 을 그대로 쓰면 단위에 끌려다닌다

위 3행은 `m/s per rad/s`, 아래 3행은 무차원. **단위가 섞인 행렬의 특이값은 물리적 의미가 없다.**

| 자세 `good` | σ_min | cond |
|---|---|---|
| 6×6, m | 0.1094 | **16.4** |
| 6×6, mm | 0.2805 | **1829.6** |
| 선속도만, m | 0.1983 | **2.5889** |
| 선속도만, mm | 198.25 | **2.5889** |

- **같은 자세인데 6×6 조건수가 112 배 달라진다.** 선속도만 쓰면 cond 는 정확히 불변.
- 6×6 의 절대값은 *"미터로 쟀다"* 는 약속 위에서만 의미가 있다.
- MoveIt `KinematicsMetrics` 가 `translation = true` 플래그를 둔 이유다.

### 이 로봇에서는 두 지표가 사실상 같은 정보다

- 무작위 30,000 자세에서 선속도 `σ_max` 범위가 **0.293 ~ 0.721** (2.5 배 안).
- `σ_max` 가 거의 상수면 `cond ≈ 상수 / σ_min`. 실제 `log σ_min` ↔ `log cond` 상관 **−0.9465**.
- 80,000 자세를 뒤져도 어긋나는 자세 **0 건**.
- → **어느 쪽을 봐도 결론이 같다.** 다만 그것이 우연(σ_max 가 좁다)임을 알고 쓸 것.

### 어디서 자를 것인가 — MoveIt 이 실패하는 지점

무작위 400 자세(**유효 `q` 의 FK 이므로 해가 반드시 있다**), 정답과 무관한 초기값,
충돌검사 끄고 `/compute_ik` 로 측정.

| `cond` (6×6, m) | 표본 | IK 성공률 |
|---|---|---|
| 10 ~ 17 | 56 | **100 %** |
| 17 ~ 30 | 98 | **100 %** |
| 30 ~ 100 | 148 | **100 %** |
| 100 ~ 1000 | 83 | 97.6 % |
| 1000 이상 | 15 | **66.7 %** |

| `σ_min` (6×6, m) | 표본 | IK 성공률 |
|---|---|---|
| < 0.001 | 11 | **81.8 %** |
| 0.001 ~ 0.01 | 58 | 91.4 % |
| 0.01 이상 | 331 | **100 %** |

**권고 기준 (이 로봇, 미터 단위):**

| `cond` | `σ_min` | 판정 | 근거 |
|---|---|---|---|
| < 100 | > 0.01 | **OK** | IK 100 % |
| 100 ~ 1000 | 0.001 ~ 0.01 | **주의** | IK 약 98 % |
| > 1000 | < 0.001 | **특이점** | IK 약 67 % |

manipulability 숫자판의 판정 밴드가 이 기준을 그대로 쓴다.

### 임계값은 목적에서 유도된다

경로가 셋이고 **서로 다른 값을 낸다.**

**(1) 관절 속도 한계.** `‖q̇‖ ≥ v / σ_min`. 이 로봇 한계 5 rad/s (joint6 만 3) → `σ_min ≥ v/5`.

| 손끝 속도 | 필요한 `σ_min` | 작업공간 미달 |
|---|---|---|
| 0.05 m/s | ≥ 0.010 | 0.3 % |
| **0.10 m/s** | **≥ 0.020** | **1.0 %** |
| 0.25 m/s | ≥ 0.050 | 4.8 % |
| 0.50 m/s | ≥ 0.100 | 21.4 % |

| preset | `σ_min` | 0.1 m/s 에 필요한 관절속도 | |
|---|---|---|---|
| `good` | 0.2373 | 0.42 rad/s | 여유 |
| `stretch` | 0.0851 | 1.18 rad/s | 여유 |
| **`elbow`** | **0.0120** | **8.34 rad/s** | **한계 5 초과 — 0.1 m/s 조차 불가** |

*"이 자세에서는 손끝을 0.1 m/s 로 못 움직인다"* 가 임의 임계값이 아니라
**로봇 제원에서 나온 결론**이 된다.

**(2) IK 수렴.** `cond > 1000` / `σ_min < 0.001` 에서 성공률 67 %.

**(3) 정확도.** 관절 오차가 손끝 오차로 증폭되는 비가 `κ`.

**세 목적이 20 배 차이 나는 숫자를 낸다** — 속도 목적 `σ_min` 0.02, IK 목적 0.001.

> **기준은 목적에서 나온다. 무엇을 막을지 먼저 정하고 그 식에서 숫자를 뽑아라.
> 셋을 섞지 마라.**

판단에 맡겨지는 것은 **안전 여유**와 **감속(soft)·정지(hard) 지점** 둘뿐이다.

### `moveit_servo` 의 17 · 30 은 다른 이야기다

- 헤더에 *"Halt if condition(Jacobian) > hard_stop_singularity_threshold"*, 기본값
  **17 감속 · 30 정지**.
- 그 구간의 IK 성공률은 **100 %** 다. 서보가 막는 것은 IK 실패가 아니라 **명령 속도의 폭발**이다.
  **두 임계값을 섞지 말 것.**
- ⚠ 17 · 30 은 **Panda 예제값**이다. 이 로봇에 그대로 쓰면 무작위 자세의 **84.8 % 가 17 을,
  60.8 % 가 30 을 넘는다** (조건수 중앙값 40.3). 임계값은 로봇마다 다시 잡아야 한다.

### MoveIt 의 이름이 헷갈린다

| API | 실제로 돌려주는 것 |
|---|---|
| `getManipulabilityIndex()` | `√det(JJᵀ)` — 부피 |
| `getManipulability()` | **`σ_min/σ_max`** — 조건수의 **역수**인데 인자명은 `condition_number` |
| 공통 | `translation = true` 면 선속도 3행만 — 단위 문제를 피하려면 켤 것 |

## 확인된 수치

전부 이 레포의 URDF · MoveIt 설정으로 실측.

### 기준점은 플랜지가 아니라 TCP 다

manipulability · workspace 는 **손끝(TCP)** 기준이다. 「닿는다」도 「잘 움직인다」도 손끝 이야기다.

- TCP = `link6` 프레임에서 **`(0, 0, 0.1358) m`**.
- 근거 — `link7`·`link8` STL 을 `link6` 좌표계로 옮기면 손가락이 `z = 0.0593 ~ 0.1358`,
  파지 중심이 `z = 0.1358`. `joint7` 원점과 같다.
- manipulability 가 이 점을 **`tcp` 프레임**으로도 내보낸다 (`link6` 의 자식).
- `tcp_offset:="[0.0,0.0,0.0]"` 면 플랜지 기준.

**기준점을 옮기면 Jacobian 이 바뀐다** — 선속도 열이 `zᵢ × (pₑ − pᵢ)` 이고 `pₑ` 가 그 점이다.

| 기준점 (팔을 편 자세) | σ (선속도) | cond | w |
|---|---|---|---|
| 플랜지 `link6` | 0.704 / 0.616 / **0.042** | 16.7 | 0.0183 |
| **TCP** | 0.895 / 0.747 / **0.085** | **10.5** | 0.0569 |

- `joint4`·`joint5` 의 지렛대가 길어져 (0.044 → 0.109, 0.091 → 0.227) 타원체가 둥글어지고
  부피가 3 배가 된다.
- `joint6` 의 선속도 기여는 **두 경우 모두 정확히 0**. TCP 가 `joint6` 축 위에 있다 —
  대칭 그리퍼의 파지 중심은 손목 롤 축 위이므로 손목을 굴려도 **자세만 바뀐다.**

### 특이점 세 자리 — 전부 존재한다

전부 TCP 기준. `σ_min` 은 6×6 최소 특이값, `cond_v` 는 선속도 조건수.

| preset | 자세 | cond_v | σ_min (6D) | 읽는 법 |
|---|---|---|---|---|
| `good` | 기준 | 2.8 | 0.104 | 둥글다 |
| `stretch` | 팔을 편다 | 10.5 | 0.0075 | 원반 |
| `elbow` | `joint3 = −2.85` + `joint5 = 0` | 77.4 | 0.000050 | 선분 |
| `wrist` | `joint5 = 0` | **3.2** | 0.000057 | **둥근데 6자유도가 죽었다** |
| `home` | 전 관절 0 | 7.8 | 0.000061 | **영자세가 곧 손목 특이점** |
| `shoulder` | 손목 중심이 `joint1` 축 위 | 5.1 | 0.000076 | 수평반경 0 |

- **손목** — `joint5 = 0` 이면 `z₄ ∥ z₆` (`|z₄·z₆| = 1.0000`). **나머지 관절값과 무관**
  (무작위 400 자세에서 σ_min 최대 6.2e-5).
- **팔꿈치** — `joint3 = −2.831 rad`(−162.2°). 역시 무관, σ_min 최대 8e-6.
  한계 −2.967 보다 **안쪽**이라 실제로 지나간다.
- **어깨** — 손목 중심이 `joint1` 축 위. 다른 특이점을 뺀 표본 2,283개에서 σ_min 최대 0.0076.

`wrist` 와 `elbow` 를 나란히 보이는 것이 핵심 — 둘 다 σ_min ≈ 0 인데 타원체는 하나는
둥글고 하나는 선분이다. **하나만 보면 놓친다.**

### 타원체는 바늘이 아니라 원반이다

팔을 편 자세의 σ 는 `0.895 / 0.747 / 0.085`. 큰 축이 **둘**이라 원반이다.

| | σ | 방향 (팔이 `+x` 로 뻗은 자세) |
|---|---|---|
| σ₁ | 0.895 | 수직 (`|u·ẑ| = 0.999`) |
| σ₂ | 0.747 | **접선** (`|u·t̂| = 1.000`) — `joint1` 이 만든다 |
| σ₃ | 0.085 | **반경** (`|u·r̂| = 0.999`) — 팔이 뻗은 방향 |

- `joint1` 이 좌우 운동을 만든다는 직관은 **맞다.** 기여가 반경 `r` 과 같고 뻗을수록
  **커진다** (0.391 → 0.615 → TCP 0.739). 그것이 σ₂ 다.
- 얇아지는 것은 **반경 방향**. 팔이 뻗은 자기 방향으로 더 나가는 능력이 죽는다.
  그것이 작업영역 경계이고 팔꿈치 특이점이다.

### 작업영역

기본 격자 `[11,13,13,5,5,1]`, 46,475 자세, TCP 기준.

| | |
|---|---|
| 최대 수평 반경 | **0.761 m** |
| base_link 원점 기준 거리 | 0.010 ~ 0.885 m |
| 높이 | −0.393 ~ 0.884 m |
| 조건수 | 중앙값 4.4 / 90 % 지점 10.3 |
| 접근 방향(바닥 ±25°)까지 맞는 영역 | **닿는 영역의 4.3 %** (2 cm 복셀, 1,292 / 29,709) |
| 계산 시간 | 16 초 |

> 최대 수평 반경 **0.761 m** 는 강의 노트의 링크 길이 합 **0.764 m** 와 사실상 같다.
> 노트의 그 숫자는 **손끝 기준**이었다는 뜻이다 — 플랜지 기준은 0.627 m 로 0.14 m 차이난다.

#### ⚠ 이 비율을 인용할 때 붙일 것 둘

**① 「부피」로 세라.** 자세 개수로 세면 한 점을 여러 자세가 찍어 과대 반영된다.
같은 격자에서 자세로 4.9 %, 부피로 4.3 %.

**② 격자에 심하게 휘둘린다.** `joint4` 고정은 접근 방향을 인위적으로 아래로 쏠리게 한다.

| 격자 | 부피 기준 |
|---|---|
| `joint4`·`joint6` 고정 (예전 기본값) | **15.7 %** |
| `joint4` 샘플링 (현재 기본값) | **4.3 %** |
| 손목을 더 촘촘히 `[9,13,13,7,7,1]` | 6.4 % |

- **이 값은 하한이다.** 손목을 촘촘히 할수록 올라간다 — 거친 격자는 「닿을 수 있는데
  못 찾은」 점을 놓친다.
- `joint6` 은 샘플링할 필요가 없다. 자기 축 회전이라 **TCP 위치도 접근 방향도 안 바뀐다**.

### 보간 두 종 (path_compare)

| | 손끝 이동 | 직선에서 최대 이탈 |
|---|---|---|
| 관절 보간 (OMPL) | 0.267 m (직선의 106.5 %) | **0.0397 m** |
| 손끝 직선 (`computeCartesianPath`) | 0.251 m | 0.0000 m |

경계 쪽으로 직선을 요구하면 `fraction = 0.62` 에서 멈춘다. 반경 0.391 m 에서 출발해
**0.546 m 에서 멈추는데, 위치만 따지면 0.627 m 까지 갈 수 있다.** 직선 보간은 손끝
*방향*도 고정한 채 가기 때문이다.

한때 IK 제한시간을 `0.005 s → 0.05 s` 로 덮었으나 **차이가 없어서 뺐다.**

| | 0.005 s (원본) | 0.05 s |
|---|---|---|
| 단일 IK 성공률 (400 자세) | 98.2 % | 98.2 % |

| 실제 이동 거리 | 0.1569 m | 0.1569 m |

「제한시간이 모자라 경로가 끊긴다」는 이 로봇·이 데모에서는 사실이 아니었다.

## 레포에서 발견한 것

### `joint_limits.yaml` 에 가속도 한계가 없다

7개 관절 전부 `has_acceleration_limits: false`.

- **Pilz 플래너(PTP·LIN)가 동작하지 않는다.** 로드는 되고 `Registered Algorithm [PTP]` 까지
  찍히지만, 계획 요청하면 `Exception caught: 'acceleration limit not set for group arm'`.
- 시간 파라미터화가 매번 경고 — `Joint acceleration limits are not defined. Using the default 1 rad/s^2`.
- 이 데모는 Pilz 를 안 쓴다(직선은 `computeCartesianPath`). 가속도 한계를 채우면 PTP·LIN
  정상 동작하는 것까지 확인.

### `joint8` 이 `ros2_control` 에 빠져 있다

`move_group` 이 **1초에 한 번** 경고한다. 강의 내내 터미널이 덮인다.

```
The complete state of the robot is not yet known.  Missing joint8
```

- 원인 — URDF 에 `joint8` 이 **`<mimic>` 없는 독립 prismatic** 으로 있는데
  `piper.ros2_control.xacro` 는 `joint1`~`joint7` 만 등록한다.
- `joint_state_broadcaster` 가 7개만 내보내고 8관절 모델을 든 `move_group` 은 상태가 안 채워진다.
- **고치면 없어지는 것까지 확인.** `joint8` 블록을 (`joint7` 과 같은 모양) 더하고
  `initial_positions.yaml` 에 `joint8: 0` 을 넣으면 경고 **0 건**.
- ⚠ 다만 그것은 **piper 설정을 고치는 일**이다. 위 원칙에 따라 적어만 둔다.

### `ompl_planning.yaml` 이 없다

그룹별 플래너 설정이 비어 `setPlannerId("RRTConnectkConfigDefault")` 같은 지정이 무시된다
(`Cannot find planning configuration for group 'arm' ... Will use defaults`).
기본값이 RRTConnect 라 결과는 같다. 데모 코드는 없는 이름을 부르지 않는다.

### `sensors_3d.yaml` 의 octomap updater 가 로드되지 않는다

`occupancy_map_monitor/DepthImageOctomapUpdater` 클래스 없음 에러가 move_group 기동마다
두 번 뜬다. obstacle 에는 영향 없다.
